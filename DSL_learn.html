Lộ trình 1: Tìm kiếm Log thần tốc

Lesson 1.1 Term vs Match: Khi nào dùng cái nào?
Use case: Bạn có ID giao dịch TX12345. Dùng term để tìm chính xác. Bạn có câu log "User login failed". Dùng match để tìm theo từ khóa.
JSON DSL
{
  "query": {
    "bool": {
      "must": [
        { "term": { "transaction_id.keyword": "TX12345" } },
        { "match": { "message": "failed" } }
      ]
    }
  }
}
Pro-tip: Luôn dùng .keyword cho các trường text nếu muốn tìm chính xác (case-sensitive).
Lesson 1.2 Wildcard & Fuzzy: Tìm khi không nhớ rõ
Use case: Tìm log của các service bắt đầu bằng auth-* hoặc tìm từ khóa bị gõ sai (vd: conection thay vì connection).
JSON DSL
{
  "query": {
    "bool": {
      "should": [
        { "wildcard": { "service.keyword": "auth-*" } },
        { "fuzzy": { "message": { "value": "conection", "fuzziness": 1 } } }
      ]
    }
  }
}

Lộ trình 2: Phân tích dữ liệu Log

Lesson 2.1 Thống kê nâng cao: Percentiles
Use case: Bạn muốn biết 95% người dùng có thời gian phản hồi dưới bao nhiêu ms (P95). Đây là chỉ số quan trọng hơn giá trị trung bình!
JSON DSL
{
  "size": 0,
  "aggs": {
    "latency_stats": {
      "percentiles": {
        "field": "latency",
        "percents": [50, 95, 99]
      }
    }
  }
}

Lộ trình 3: Tự động hóa & Xử lý phức tạp

Lesson 3.1 Nested Objects: Lọc chính xác trong mảng
Use case: Tìm document có user có name="admin" VÀ permission="write" trong cùng một object thuộc mảng users.
JSON DSL
{
  "query": {
    "nested": {
      "path": "users",
      "query": {
        "bool": {
          "must": [
            { "term": { "users.name": "admin" } },
            { "term": { "users.permission": "write" } }
          ]
        }
      }
    }
  }
}
