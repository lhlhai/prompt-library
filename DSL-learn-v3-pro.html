Bài 1 — exists query: Phát hiện Log Thiếu Field

💡 Deep Dive: Tại sao log thiếu field lại nguy hiểm?

Trong an ninh mạng, một event không có kết quả (outcome) là một "điểm mù". Query exists không chỉ để tìm lỗi, mà là để kiểm toán độ tin cậy của hệ thống log.

GET logs-*/_search
{
  "query": {
    "bool": {
      "must": [{ "match": { "event.category": "authentication" } }],
      "must_not": [{ "exists": { "field": "event.outcome" } }]
    }
  }
}

🎯 Bài tập thực hành

  • Tìm HTTP request thiếu field source.ip
  • Tìm log error nhưng thiếu error.message

Bài 2 — Sensitive Data Detection

🧠 Đào sâu: Vấn đề của Match Phrase

Dùng match_phrase đơn thuần rất dễ sót. Hãy kết hợp với Fuzzy Search để bắt được cả những dữ liệu bị cố tình làm nhiễu.

GET logs-*/_search
{
  "query": {
    "bool": {
      "should": [
        { "match_phrase": { "message": "password" } },
        { "match_phrase": { "message": "token" } }
      ],
      "minimum_should_match": 1
    }
  }
}

Bài 3 — regexp query: Phát Hiện Log Injection

GET logs-*/_search
{
  "query": {
    "bool": {
      "should": [
        { "match_phrase": { "message": "\\n" } },
        { "regexp": { "message": ".*(%0a|%0d|%0d%0a).*" } }
      ],
      "minimum_should_match": 1
    }
  }
}
