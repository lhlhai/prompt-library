NỀN TẢNG PYTHON & PYTEST

⏱️ 2–3 TUẦN

Mục tiêu

  • Hiểu tư duy lập trình cơ bản, quản lý môi trường, cấu trúc project
  • Nắm vững Pytest: fixture, assertion, parametrize, test lifecycle

Nội dung cốt lõi

  • Python: variables, list/dict, loop, function, class/OOP cơ bản, module/package
  • Môi trường: venv, pip, requirements.txt
  • Pytest: setup/teardown, fixtures (scope: function/module/session), assert, @pytest.mark, @pytest.mark.parametrize, pytest.ini
  • Tư duy: Test case → Test script, Data-driven mindset

Bài thực hành

  • Viết script đọc CSV → tính toán → xuất kết quả
  • Viết 8 test case Pytest cho 1 module tính toán đơn giản (dùng fixture, parametrize, custom mark)
  • Tạo conftest.py với fixture setup_data reuse cho nhiều test

✅ CHECKPOINT (BẮT BUỘC)

  • Chạy pytest -v không lỗi môi trường, hiểu rõ scope của fixture
  • Không dùng print() để debug, dùng logging hoặc pytest report
  • Tự viết được assertion custom, hiểu tại sao test fail/pass
Rule: Chưa đạt → ôn lại OOP + fixture. Không được nhảy sang Playwright.

PLAYWRIGHT CORE – LÀM CHỦ BROWSER AUTOMATION

⏱️ 3–4 TUẦN

Mục tiêu

  • Hiểu kiến trúc Playwright, selector strategy, auto-wait, context isolation
  • Viết script automation ổn định, không phụ thuộc time.sleep()

Nội dung cốt lõi

  • Cài đặt: pip install playwright && playwright install
  • Sync API: sync_playwright(), browser, context, page
  • Selector: CSS, text=, role=, get_by_* (khuyến nghị)
  • Actions: click(), fill(), select_option(), check(), press()
  • Wait & Stability: Auto-wait mechanism, expect(), handling dynamic DOM
  • Advanced UI: Dialog, iframe, file upload/download, screenshot/video

Bài thực hành

  • Automate flow: Login → Search → Filter → Extract table data → Logout
  • Xử lý: Modal popup, dropdown async load, form validation error
  • Capture screenshot/video khi test fail

✅ CHECKPOINT (BẮT BUỘC)

  • Chạy ổn định trên Chromium, Firefox, WebKit (không crash)
  • 0 lần dùng time.sleep(), chỉ dùng auto-wait hoặc expect().to_be_visible()
  • Xử lý được iframe & file download trong cùng context
Rule: Script còn flaky → quay lại học expect() & selector strategy.

PLAYWRIGHT + PYTEST INTEGRATION

⏱️ 2–3 TUẦN

Mục tiêu

  • Tích hợp Playwright vào Pytest, tận dụng plugin chính thức
  • Chạy parallel, quản lý browser/context qua fixture, generate report

Nội dung cốt lõi

  • Plugin: pytest-playwright
  • Fixture built-in: page, browser, browser_context
  • conftest.py: Override fixture, login setup once per session
  • Parallel: pytest -n auto, thread-safety trong Playwright
  • Report: pytest-html, allure-playwright (optional)
  • Config: pytest.ini, playwright.config.py (nếu cần)

Bài thực hành

  • Refactor toàn bộ Phase 1 thành Pytest tests
  • Tạo fixture authenticated_page (login 1 lần, reuse context)
  • Chạy pytest -n 4 → verify không conflict state giữa workers
  • Generate HTML report + attach screenshot on failure

✅ CHECKPOINT (BẮT BUỘC)

  • Parallel run 100% pass, không leak memory/context
  • Fixture scope="session" hoạt động đúng, không login lại mỗi test
  • Report hiển thị rõ: test name, duration, screenshot, browser version
Rule: Parallel fail → kiểm tra context isolation & fixture scope.

TEST DESIGN & ADVANCED PLAYWRIGHT

⏱️ 3–4 TUẦN

Mục tiêu

  • Viết test maintainable, xử lý scenario phức tạp, mock network, debug chuyên sâu
  • Áp dụng Page Object Model (POM) cơ bản

Nội dung cốt lõi

  • POM: Tách locator + action thành class, reuse flow
  • Network: route(), mock, abort, intercept API response
  • Auth: storage_state.json, bypass login
  • Debug: Trace Viewer (playwright show-trace), pause(), network panel
  • Anti-pattern: Hardcoded wait, CSS brittle, over-reuse page instance
  • Retry & Flaky control: pytest-rerunfailures, pytest.mark.flaky

Bài thực hành

  • Implement POM cho e2e flow: E-commerce checkout (3 page classes)
  • Mock API /products → trả về JSON custom, verify UI update
  • Lưu storage_state sau login → inject vào test khác
  • Dùng Trace Viewer debug 1 test fail → fix root cause

✅ CHECKPOINT (BẮT BUỘC)

  • Flaky rate < 5% sau 50 lần run liên tiếp
  • POM code clean: không có locator trùng, không expose page ra ngoài test
  • Mock hoạt động chính xác, không gọi real API
Rule: Chưa đạt → refactor POM + luyện Trace Viewer đến khi debug thành thạo.

BEST PRACTICES & CI/CD PIPELINE

⏱️ 2 TUẦN

Mục tiêu

  • Đưa test vào pipeline tự động, đảm bảo chất lượng code, thông báo kết quả

Nội dung cốt lõi

  • Linting/Formatting: ruff, black, isort
  • Pre-commit: pre-commit hook, block push nếu fail lint/test
  • CI/CD: GitHub Actions / GitLab CI, matrix strategy (browser × OS)
  • Caching: playwright install cache, pip cache
  • Tagging: @smoke, @regression, @api → chạy selective
  • Notification: Slack/Email webhook khi pipeline fail

Bài thực hành

  • Tạo .github/workflows/e2e.yml → chạy trên PR push
  • Config matrix: browser: [chromium, firefox], os: [ubuntu-latest]
  • Thêm ruff + black vào pipeline, block merge nếu fail
  • Gửi report summary + screenshot link về Slack khi fail

✅ CHECKPOINT (BẮT BUỘC)

  • Pipeline xanh 100% khi push code đúng chuẩn
  • Matrix run đúng 2 browser × 1 OS, thời gian < 10 phút
  • Code pass lint, không có warning ruff
Rule: Pipeline đỏ → fix ngay, không merge. Không sang Phase 5.
