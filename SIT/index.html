NẮM VỮNG KHÁI NIỆM

Lý thuyết, thật gọn.

Mở từng mục để xem định nghĩa, thời điểm sử dụng và ví dụ thực tế.

ITIntegration TestKiểm thử tích hợp module⌄

TL;DR: Kiểm tra interface giữa hai hoặc một vài module/component ghép với nhau, thường trong cùng một hệ thống.

Định nghĩa

Integration Test xác minh các unit/module trao đổi dữ liệu và phối hợp đúng tại điểm kết nối. Phạm vi nhỏ, tập trung vào interface giữa các thành phần như service, repository hay API nội bộ.

Khi nào dùng

Sau khi các unit riêng lẻ đã được kiểm tra, trước khi xác nhận toàn bộ hệ thống hoặc tích hợp với hệ thống bên ngoài.

Ai thường thực hiện

Thường là developer; QA có thể tham gia xây dựng hoặc chạy bộ kiểm thử tích hợp.

Input / Output điển hình

Input: request, dữ liệu giả lập hoặc bản ghi test. Output: response, dữ liệu lưu/đọc và kết quả phối hợp giữa các module.

Ví dụ thực tế

Kiểm tra API đăng nhập gọi Auth Service và Auth Service đọc đúng tài khoản từ Database.

Đừng nhầm: “Integration” trong IT ở đây là tích hợp module/component với phạm vi nhỏ; không đồng nghĩa kiểm tra nhiều hệ thống/deployable services — đó là trọng tâm của SIT.
STSystem TestKiểm thử toàn hệ thống⌄

TL;DR: Kiểm tra toàn bộ hệ thống như một black-box để xác nhận hành vi end-to-end theo requirement.

Định nghĩa

System Test đánh giá hệ thống hoàn chỉnh so với yêu cầu chức năng và phi chức năng. Người kiểm thử quan sát đầu vào và đầu ra, không tập trung vào cách các module bên trong được cài đặt.

Khi nào dùng

Sau khi các thành phần đã tích hợp thành hệ thống có thể kiểm thử; thường trước UAT hoặc phát hành.

Ai thường thực hiện

QA/tester thường phụ trách, phối hợp với dev để chuẩn bị môi trường và dữ liệu.

Input / Output điển hình

Input: hành động người dùng và dữ liệu theo kịch bản. Output: kết quả hiển thị, trạng thái và hành vi so với requirement.

Ví dụ thực tế

Người dùng điền biểu mẫu đăng ký, gửi yêu cầu và nhận màn hình xác nhận đúng quy định.

Đừng nhầm: System Test nhìn toàn bộ sản phẩm như một khối; nó không có mục tiêu chính là kiểm tra riêng từng interface nội bộ hay kết nối giữa các hệ thống triển khai độc lập.
SITSystem Integration TestKiểm thử tích hợp liên hệ thống⌄

TL;DR: Kiểm tra các subsystem/service độc lập ghép nối với nhau qua API, message queue hoặc network.

Định nghĩa

SIT xác minh luồng dữ liệu và hợp đồng tích hợp giữa nhiều hệ thống con hoặc deployable units. Phạm vi rộng hơn IT và thường bao gồm phụ thuộc bên ngoài.

Khi nào dùng

Khi các hệ thống liên quan đã sẵn sàng tích hợp; thường trước UAT để tìm lỗi ở ranh giới hệ thống.

Ai thường thực hiện

QA phối hợp với developer, DevOps hoặc System Engineer phụ trách các service và môi trường.

Input / Output điển hình

Input: giao dịch/ message đầu-cuối qua các service. Output: phản hồi nhất quán, trạng thái đồng bộ và xử lý lỗi xuyên hệ thống.

Ví dụ thực tế

Payment Service gọi Bank API, phát sự kiện thanh toán qua Kafka và Notification Service gửi thông báo đúng trạng thái.

Đừng nhầm: SIT không phải chỉ là “IT lớn hơn” theo số lượng module; điểm phân biệt là ranh giới giữa các subsystem/service độc lập, thường giao tiếp qua mạng hoặc message broker.

QUYẾT ĐỊNH NHANH

Bạn đang test cái gì?

Bắt đầu từ đối tượng cần xác minh
Một vài module/component đang phối hợp trong cùng hệ thống?↓ CóIntegration Test (IT)
Toàn bộ sản phẩm theo requirement, không soi nội bộ?↓ CóSystem Test (ST)
Nhiều subsystem/service độc lập giao tiếp qua API/queue/network?↓ CóSystem Integration Test (SIT)

Nếu câu trả lời chưa rõ, xác định trước ranh giới của đơn vị triển khai và mục tiêu kiểm thử.

KẾT QUẢ CỦA BẠN

VỀ PHÒNG MÔ PHỎNG

Học nhanh bằng mắt.

Một tài liệu tương tác nhỏ cho người học QA/Tester và developer.

01

Không cần cài đặt

Ứng dụng chỉ gồm HTML, CSS và JavaScript thuần. Mở trực tiếp index.html hoặc host miễn phí bằng GitHub Pages.

02

Phạm vi là điểm mấu chốt

IT kiểm tra kết nối giữa module; ST xác minh cả hệ thống theo requirement theo cách black-box; SIT kiểm tra tích hợp giữa subsystem/service độc lập.

03

Ghi chú triển khai

Không dùng thư viện, API hay tài nguyên bên ngoài. Có thể tải repo và tùy biến ví dụ, màu sắc hoặc các bước mô phỏng.

DEPLOY LÊN GITHUB PAGES

Xuất bản miễn phí

  1. Tạo repository tên sit-vs-st-vs-it-sim.
  2. Đưa index.html, style.css, app.js và README.md vào thư mục gốc rồi push lên nhánh main.
  3. Mở Settings → Pages, chọn Deploy from a branch → main → /(root) → Save.
  4. Trang sẽ có địa chỉ https://<username>.github.io/sit-vs-st-vs-it-sim/.

Có thể kiểm thử trước bằng cách mở file index.html trực tiếp trong trình duyệt.
