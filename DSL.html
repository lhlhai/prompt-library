Lộ trình học Query DSL thực chiến

Từ những câu lệnh cơ bản đến các truy vấn phân tích phức tạp. Dành riêng cho Tester muốn làm chủ dữ liệu log.

Mục lục bài học

  • Cơ bản: Tìm kiếm chính xác
  • Trung cấp: Logic & Full-text
  • Nâng cao: Aggregation & Script

Phần 2: Lộ trình học tập & Ví dụ thực chiến

Cấp độ 1: Tìm kiếm chính xác (Term Level Queries)

Lesson 1 Term Query - Tìm chính xác
Tình huống: Bạn muốn tìm tất cả các log có status_code đúng bằng 500 hoặc service_name là "auth-service".
JSON DSLGET /logs/_search
{
  "query": {
    "term": {
      "status_code": 500
    }
  }
}
Lưu ý: term query không thực hiện phân tách từ (analysis), nó tìm chính xác giá trị bạn truyền vào. Thường dùng cho các trường kiểu keyword, numeric, hoặc boolean.
Lesson 2 Range Query - Tìm trong khoảng
Tình huống: Tìm các lỗi xảy ra trong 1 giờ qua hoặc các request có thời gian phản hồi (latency) > 2000ms.
JSON DSLGET /logs/_search
{
  "query": {
    "range": {
      "response_time": {
        "gt": 2000, // Greater than
        "lte": 5000 // Less than or equal
      }
    }
  }
}
Các tham số phổ biến: gt (>), gte (>=), lt (<), lte (<=). Đối với thời gian, bạn có thể dùng "now-1h".

Cấp độ 2: Logic & Tìm kiếm toàn văn (Full-text)

Lesson 3 Bool Query - Kết hợp logic phức tạp
Tình huống: Tìm log của service "order", có level "ERROR", nhưng KHÔNG phải lỗi "Timeout", và NÊN có từ khóa "database".
JSON DSL
{
  "query": {
    "bool": {
      "must": [ // Bắt buộc phải có (AND)
        { "term": { "service": "order" } },
        { "term": { "level": "ERROR" } }
      ],
      "must_not": [ // Bắt buộc KHÔNG có (NOT)
        { "match": { "message": "Timeout" } }
      ],
      "should": [ // Có thì tốt, tăng điểm số (OR)
        { "match": { "message": "database" } }
      ],
      "filter": [ // Giống must nhưng không tính điểm (nhanh hơn, có cache)
        { "range": { "@timestamp": { "gte": "now-1d" } } }
      ]
    }
  }
}
Lesson 4 Match Phrase - Tìm cụm từ chính xác
Tình huống: Bạn tìm cụm từ "connection refused" nhưng cho phép giữa 2 từ này có tối đa 1 từ khác chen vào.
JSON DSL
{
  "query": {
    "match_phrase": {
      "message": {
        "query": "connection refused",
        "slop": 1
      }
    }
  }
}
slop: 1 giúp khớp cả chuỗi "connection is refused". Rất hữu ích khi log có các từ nối thay đổi.

Cấp độ 3: Phân tích & Thống kê (Aggregations)

Lesson 5 Terms Aggregation - Thống kê top lỗi
Tình huống: Bạn muốn biết 5 loại exception_class nào xuất hiện nhiều nhất trong hệ thống.
JSON DSL
{
  "size": 0, // Không lấy danh sách log, chỉ lấy kết quả thống kê
  "aggs": {
    "top_errors": {
      "terms": {
        "field": "exception_class.keyword",
        "size": 5
      }
    }
  }
}
Lesson 6 Sub-Aggregation - Thống kê lồng nhau
Tình huống: Với mỗi service, hãy tính thời gian phản hồi trung bình (average latency).
JSON DSL
{
  "size": 0,
  "aggs": {
    "by_service": {
      "terms": { "field": "service_name.keyword" },
      "aggs": {
        "avg_latency": {
          "avg": { "field": "latency" }
        }
      }
    }
  }
}
Đây là sức mạnh thực sự của DSL. Bạn có thể lồng hàng chục tầng aggregation để đào sâu dữ liệu mà UI không bao giờ làm được.
Lesson 7 Scripting - Tính toán động
Tình huống: Log chỉ có start_time và end_time, bạn muốn tính duration ngay khi query.
JSON DSL
{
  "script_fields": {
    "duration_ms": {
      "script": {
        "source": "doc['end_time'].value.toInstant().toEpochMilli() - doc['start_time'].value.toInstant().toEpochMilli()"
      }
    }
  }
}

Mẹo cuối: Hãy luôn sử dụng tab Dev Tools trong Kibana để được gợi ý cú pháp (Auto-complete).
