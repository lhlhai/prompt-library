Từ Kibana UI đến Query DSL

Cẩm nang nâng tầm kỹ năng log analysis dành cho Automation Tester chuyên nghiệp. Chuyển từ người dùng công cụ sang người làm chủ dữ liệu.

Mục lục

  • 1. So sánh UI vs DSL
  • 2. Lộ trình học tập
  • 3. Ý tưởng phát triển

Phần 1: Tại sao Query DSL là "Vũ khí tối thượng"?

UI filter của Kibana (KQL/Lucene) rất tiện cho các thao tác nhanh, nhưng Query DSL mới thực sự mở ra sức mạnh không giới hạn.

Khía cạnh UI Filter (KQL) Query DSL (JSON)
Logic phức tạp Chỉ hỗ trợ AND, OR, NOT cơ bản. Khó lồng nhau sâu. Cấu trúc cây bool lồng nhau tuỳ ý (must, should, filter).
Tìm kiếm mờ Hạn chế qua ~. Khó kiểm soát. Kiểm soát fuzziness, prefix_length cực kỳ chính xác.
Regexp Không hỗ trợ trực tiếp hoặc rất hạn chế. Hỗ trợ đầy đủ regex để khớp pattern ID, phone, log format.
Phrase matching Có thể dùng "..." nhưng không chỉnh được khoảng cách. match_phrase với slop cho phép các từ cách nhau một khoảng.
Aggregation Visualization có sẵn, không tuỳ chỉnh sâu. Toàn quyền với aggs lồng nhau nhiều tầng, tính toán thống kê phức tạp.
Scripting Không hỗ trợ. script_fields cho phép tính toán dữ liệu ngay lúc query.
Nested objects Dễ sai logic khi lọc trên mảng. nested query giúp truy vấn chính xác từng phần tử trong mảng.
Tự động hoá Thao tác tay, khó tái sử dụng. JSON thuần, dễ dàng nhúng vào Python, Postman, JMeter.
Phân trang Cơ bản, chậm khi lùi sâu (>10k doc). search_after cho phép duyệt hàng triệu record mượt mà.

Phần 2: Lộ trình học Query DSL cho Tester

Nguyên tắc vàng: Học qua ví dụ thực tế, thực hành trên Dev Tools và không cần thuộc lòng - hãy luôn mở Reference!
Giai đoạn 1: 1-2 ngày
Làm quen với sân chơi

Mở Dev Tools, học các lệnh quản lý index cơ bản: GET _cluster/health, GET /index/_search, POST /index/_doc. Tạo dữ liệu giả lập để thực hành.

Giai đoạn 2: 3-5 ngày
Chuyển đổi từ KQL sang DSL

Viết lại các filter quen thuộc bằng DSL. Mẹo: Dùng Inspect trên Discover để xem DSL mà Kibana tự sinh ra và học từ đó.

Giai đoạn 3: 1 tuần
Làm chủ các loại query chuyên biệt

Học match, match_phrase, wildcard, fuzzy và đặc biệt là nested query. Mỗi ngày chọn một loại lỗi thực tế để viết query.

Giai đoạn 4: 1-2 tuần
Aggregation – Sức mạnh phân tích

Học terms, date_histogram. Thực hành bài toán: "Tính số lượng đơn hàng thất bại theo mã lỗi trong 1 giờ" hoặc "Tìm 10 user chậm nhất".

Liên tục
Tối ưu và tự động hoá

Dùng profile: true để soi hiệu năng. Đưa query vào Python script hoặc Postman. Xây dựng bộ "query thần thánh" cho cả team.

Phần 3: Ý tưởng phát triển & Show-off

Khi đã thành thạo, hãy thử sức với các dự án nhỏ này để nâng tầm sự nghiệp:

🚀
Log-Hawk CLI Tool

Viết tool Python (elasticsearch-py + rich) để query log cực nhanh từ terminal, trả về bảng lỗi đẹp mắt kèm link Kibana.

🤖
AI - Chat với Log

Tích hợp LLM (OpenAI/Gemini) để sinh Query DSL từ câu hỏi tiếng Việt tự nhiên của đồng nghiệp.

🔧
Auto-Bug Ticketing

Script tự động theo dõi log, phân cụm lỗi bằng ML và tự tạo Jira issue kèm đầy đủ thông tin phân tích.

📊
Regression Log Assertion

Đưa DSL vào CI/CD pipeline. Sau khi chạy test, tự động check log: nếu lỗi 5xx tăng đột biến -> Fail pipeline ngay.

🎵
Âm thanh cảnh báo

Script phát tiếng "Toang!", "Bùm!" qua loa văn phòng mỗi khi hệ thống có lỗi 500. Vừa vui vừa cảnh báo tức thì!

🖥️
Màn hình War Room

Dashboard terminal real-time hiển thị top service lỗi, đếm ngược sự cố... cực kỳ chuyên nghiệp.
